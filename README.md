# 🎓 CampusConnect — College Event & Club Management System

A full-stack MERN app where students discover and register for college events, club admins manage their events and attendance, and a super admin runs the whole platform. Students get a **QR-code ticket** for every event they register for.

**Stack:** React + Vite + TypeScript · Tailwind CSS + shadcn/ui-style components · Zustand · React Hook Form + Zod · Node.js + Express · MongoDB (Mongoose) · JWT auth · Cloudinary (optional image upload)

---

## ✨ Features

| Role | What they can do |
|---|---|
| **Student** | Browse events · search & filter (club, category, date) · register (seat-checked) · QR ticket + download · cancel registration · edit profile |
| **Club Admin** | Dashboard stats · create / edit / delete own club's events · see registrations · mark attendance · export CSV |
| **Super Admin** | Platform stats · manage clubs · manage users (promote to club admin, assign club) · manage all events |

Plus: protected routes with role-based redirects, loading skeletons, toast notifications, fully responsive dark UI.

## 🧰 1. Prerequisites (install once)

| Tool | Check it works | Get it |
|---|---|---|
| **Node.js 18+** | `node -v` | https://nodejs.org (LTS) |
| **Git** | `git --version` | https://git-scm.com |
| **MongoDB Community Server** | `mongosh` connects | see below |

### Installing MongoDB
- **macOS (Homebrew):**
  ```bash
  brew tap mongodb/brew
  brew install mongodb-community
  brew services start mongodb-community
  ```
- **Windows:** download *MongoDB Community Server* from https://www.mongodb.com/try/download/community and keep **"Install MongoDB as a Service"** ticked. It then starts automatically.
- **Linux (Ubuntu):** follow https://www.mongodb.com/docs/manual/administration/install-on-linux/ then `sudo systemctl start mongod`.

> No local MongoDB? Use a free MongoDB Atlas cluster instead and paste its connection string as `MONGO_URI` in `backend/.env` (after step 3).

## 🚀 2. Quick start (4 commands)

```bash
git clone <REPO_URL>
cd <REPO_FOLDER>

npm run setup     # installs everything + creates backend/.env and frontend/.env
npm run seed      # loads demo users, clubs and events
npm run dev       # starts backend AND frontend together
```

Now open **http://localhost:5173** 🎉

The API runs on **http://localhost:5001** (opening it in a browser shows `{"ok":true,...}`).

> ⚠️ `npm run seed` **wipes the `event-system` database** and recreates demo data. Run it only when you want a fresh start.

## ⚙️ 5. Configuration

`npm run setup` creates these for you. Edit them only if needed.

**`backend/.env`**
```env
PORT=5001
MONGO_URI=mongodb://127.0.0.1:27017/event-system
JWT_SECRET=<auto-generated>
CLIENT_URL=http://localhost:5173
CLOUDINARY_CLOUD_NAME=      # optional
CLOUDINARY_API_KEY=         # optional
CLOUDINARY_API_SECRET=      # optional
```

**`frontend/.env`**
```env
VITE_API_URL=http://localhost:5001/api
```

- Change the port? Update `PORT` in `backend/.env` **and** `VITE_API_URL` in `frontend/.env`, then restart (Vite reads `.env` only at startup).
- **Image upload** (event covers, profile photo) needs free Cloudinary keys. Everything else works without them, and the seeded events use sample images from the internet.

## 🔌 7. API overview

All routes are under `/api`. 🔒 = needs `Authorization: Bearer <token>`.

| Area | Endpoints |
|---|---|
| Auth | `POST /auth/register` · `POST /auth/login` · 🔒`GET /auth/me` · 🔒`PUT /auth/me` |
| Events | `GET /events` (`?q=&club=&category=&date=&upcoming=`) · `GET /events/:id` · 🔒`POST /events` · 🔒`PUT /events/:id` · 🔒`DELETE /events/:id` |
| Registrations | 🔒`POST /registrations` · 🔒`GET /registrations/my` · 🔒`GET /registrations/event/:eventId` · 🔒`PATCH /registrations/:id/attendance` · 🔒`DELETE /registrations/:id` |
| Clubs | `GET /clubs` · 🔒`POST /clubs` · 🔒`PUT /clubs/:id` · 🔒`DELETE /clubs/:id` |
| Users | 🔒`GET /users` · 🔒`PATCH /users/:id/role` (super admin only) |
| Other | 🔒`POST /upload` (Cloudinary) · 🔒`GET /stats/admin` · 🔒`GET /stats/club` |

**Design notes:** passwords hashed with bcrypt · JWT valid 7 days · role checks enforced on the server (club admins can only touch their own club's events) · seat booking uses an atomic MongoDB update so the last seat can't be double-booked · a unique index stops duplicate registrations.

## 🛠 8. Troubleshooting

| Problem | Fix |
|---|---|
| `MongoDB connection failed` | MongoDB isn't running. Start it (see step 1) and rerun `npm run dev`. |
| `EADDRINUSE: port 5001` | Something else uses 5001. Change `PORT` in `backend/.env` and `VITE_API_URL` in `frontend/.env`. (macOS uses port 5000 for AirPlay, which is why we use 5001.) |
| "Cannot reach the server" in the browser | Backend isn't running or `VITE_API_URL` is wrong. Restart `npm run dev`. |
| CORS error in browser console | `CLIENT_URL` in `backend/.env` must equal the address you opened, e.g. `http://localhost:5173`. Restart. |
| Can't log in with demo accounts | You haven't run `npm run seed`. |
| Image upload fails | Add Cloudinary keys to `backend/.env` and restart. Optional feature. |
| `npm run setup` fails on install | Check `node -v` is 18+, delete `node_modules` folders, retry. |
| Want to run the parts separately | `cd backend && npm run dev` and, in another terminal, `cd frontend && npm run dev`. |
